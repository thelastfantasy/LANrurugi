Every type and function a plugin author can use, generated by `deno doc` straight from **the same
TypeScript the plugin runtime loads** (`plugin-sdk.ts` and `dispatcher.ts` under
`crates/lanrurugi-plugin/dispatcher/`, plus `plugins/legacy-globals.d.ts`) — so it cannot drift from
what the host actually does.

<p>
  <a class="sdk-launch" href={import.meta.env.DOCS_SDK_URL}>Open the SDK reference →</a>
</p>

That reference supports symbol search, grouping by type/interface/function, and shows each symbol's
own documentation comment. The same content is also published as machine-readable JSON
(`plugin-sdk.json`) for tooling.

:::note[Why it is not part of this sidebar's page tree]
`deno doc --html` produces a **self-contained static site** with its own search, dark mode and symbol
index. Re-rendering all of that inside Starlight would mean writing it again rather than reusing it,
so it is served as a sub-path of this site instead.
:::
