Install (Docker / NAS)

The LANrurugi server is one resident process holding the static frontend, the HTTP API, the file watcher and background jobs; plugins, e-book parsing and AI inference run in subprocesses started on demand. It has its own database and neither reads nor changes LANraragi’s, so the two can run side by side.

Moving from LANraragi

  1. In LANraragi, go to Settings → Database Backup/Restore → Backup Database and save the JSON. LANraragi can keep running.
  2. Start LANrurugi with the same manga directory as its library. Thumbnails and the database need mounts too, but in new directories, not LANraragi’s. The converter on the homepage generates this from LANraragi’s deployment command or compose file.
  3. Sign in with the default password kamimamita; the first-run wizard asks you to change it.
  4. Upload the JSON in the wizard’s “Import from a LANraragi backup” step (or later under Settings → Database Backup/Restore). Tags, categories, tankoubons and stamps come back; reading progress is not part of the backup.

Prefer not to use containers? There are native packages for Linux, macOS (Apple Silicon) and FreeBSD.

Then open http://<server>:3000 in a browser. Redis is bundled in the image; no separate database container is needed. The four mounted directories:

Host path Path in the container Purpose
./data/manga /home/koyomi/lanrurugi/content Your library
./data/thumb /home/koyomi/lanrurugi/thumb Thumbnail cache
./data/database /home/koyomi/lanrurugi/database Redis data (LANrurugi only)
./data/models /home/koyomi/lanrurugi/models Local model cache for recommendations and tankoubon grouping

To serve it on a domain over HTTPS, see Reverse proxy.

Using a different port

Section titled “Using a different port”

The image always listens on 3000 inside the container. Changing only the host side is enough: edit the left half of ports (or of docker run -p).

To change the port inside the container too (network_mode: host, or something else already holds 3000), override the image’s command. The image’s CMD already carries --bind [::]:3000, and a command-line flag beats an environment variable, so -e LANRURUGI_BIND=0.0.0.0:8080 does not work:

In Compose that is the command key:

--bind takes one whole address:port: [::] (the default) listens on IPv4 and IPv6, 0.0.0.0 on all IPv4 interfaces only, 127.0.0.1 on loopback for a reverse proxy. A bare port is not accepted.

Where the image is published

Section titled “Where the image is published”

The same image, for amd64 and arm64, is published to two registries:

Registry Image
GitHub Container Registry (recommended) ghcr.io/thelastfantasy/lanrurugi
Docker Hub jade913/lanrurugi

The examples above use GitHub’s registry. Docker Hub limits how often anonymous users can pull; if your NAS panel only searches Docker Hub, or you simply prefer it, use jade913/lanrurugi instead. latest points at the newest release; a specific version number works too.

First login

Section titled “First login”

The first visit opens the first-run wizard: change the admin password, add a DeepSeek API key for the AI features, and import a LANraragi backup. Every step can be skipped, and the wizard can be rerun from Settings later.

A brand-new instance — or one migrated from an old installation whose password was never changed — uses LANraragi’s own default administrator password, kamimamita.

Change the password first thing

Change it in the settings page immediately after logging in. Do not leave an instance reachable from outside your local network while it still uses the default password.

Versions are pinned in .mise.toml, and mise install reproduces them exactly (Rust, Node, Deno, pnpm, plus sccache/mold).

CLI subcommands

Section titled “CLI subcommands”
  • lanrurugi serve — runs the HTTP API, static frontend, file watcher and plugin pool in one process.
  • lanrurugi rebuild-index — recomputes every archive’s ID with the size-aware algorithm and surfaces files that were historically hidden by a mistaken merge.
  • lanrurugi bench — generates a synthetic library and runs a concurrency/throughput comparison against a running legacy instance.
