安装（Docker / NAS）

LANrurugi 的服务端是一个常驻进程，前端静态资源、HTTP API、文件监视器和后台任务都在里面；插件、电子书解析和 AI 推理在按需启动的子进程里运行。它有自己的数据库，不读取也不改动 LANraragi 的数据库，两者可以同时运行。

从 LANraragi 迁移

  1. 在 LANraragi 的设置 →「Database Backup/Restore」→「Backup Database」下载备份 JSON，LANraragi 可以继续运行。
  2. 启动 LANrurugi：书库挂载和 LANraragi 相同的漫画目录；缩略图和数据库也要挂载，但必须用新的目录，不要和 LANraragi 的相同。主页上的转换器能根据 LANraragi 的部署命令或 compose 文件生成。
  3. 用默认密码 kamimamita 登录，首次运行向导会提示你修改。
  4. 在向导的「从 LANraragi 备份导入」一步上传 JSON（之后也能在设置 →「数据库备份/恢复」里导入）。标签、分类、 合集和 stamps 会恢复，阅读进度不在备份里。

不想用容器的话，也可以用 Linux、macOS（Apple Silicon）和 FreeBSD 的原生安装包。

启动后在浏览器打开 http://<服务器地址>:3000。镜像自带 Redis，不需要额外的数据库容器。四个挂载目录：

宿主机路径 容器内路径 用途

./data/database /home/koyomi/lanrurugi/database Redis 数据（LANrurugi 专用）
./data/models /home/koyomi/lanrurugi/models 推荐和单行本整理用的本地模型缓存

换一个端口

Section titled “换一个端口”

镜像内部固定监听 3000。只换宿主机这一侧就够了：改 ports 或 docker run -p 的左边。

如果容器内部也要换（network_mode: host，或者 3000 已被别的服务占用），要覆盖镜像的启动命令。 镜像的 CMD 里已经写死 --bind [::]:3000，而命令行参数优先于环境变量，所以 -e LANRURUGI_BIND=0.0.0.0:8080 不会生效。

--bind 的值是一整个 地址:端口：[::]（默认）同时监听 IPv4 和 IPv6，0.0.0.0 监听所有 IPv4 网卡， 127.0.0.1 只给本机（配合反向代理）；只写端口不行。

镜像来源

Section titled “镜像来源”

同一个镜像同时发布在两个仓库，内容完全相同，都包含 amd64 和 arm64 两种架构：

仓库 镜像名
GitHub Container Registry（推荐） ghcr.io/thelastfantasy/lanrurugi
Docker Hub jade913/lanrurugi

上面的示例用的是 GitHub 的仓库。Docker Hub 对未登录用户有拉取次数限制；如果你的 NAS 面板只能从 Docker Hub 搜索镜像，或者你更习惯用它，把镜像名换成 jade913/lanrurugi 即可。latest 指向最新的正式版本， 也可以写具体的版本号。

CLI 子命令

Section titled “CLI 子命令”
  • lanrurugi serve——在同一个进程里运行 HTTP API、静态前端、文件监视器与插件池。
  • lanrurugi rebuild-index——用大小感知算法重新计算每个档案的 ID，并发现历史上曾被误判合并而隐藏的 文件。
  • lanrurugi bench——生成合成库，并针对一个正在运行的旧版实例做并发/吞吐量对比。
