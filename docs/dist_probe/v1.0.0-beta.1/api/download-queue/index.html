Section titled “对比队列项的 SSE 流式版本”

GET /download_queue/{id}/compare/stream——上面 [compare_queue_item] 的 SSE 流式孪生版本，依据 issue #77 自己确认的两阶段设计（完整的阶段一/阶段二拆分见 lanrurugi_imgcompare::compare_archives_streaming 自身的文档）：开启一条 EventSource 兼容的流（用 GET 而非 POST——EventSource 无法发送请求体，也无法使用任何其他 HTTP 方法），每当出现一个 CompareEvent::Sample 就发出一个 event: sample（先粗后精，精确的替换样本随后陆续流入），最后发出一个终止性的 event: done，携带 ComparisonResult 其余字段——绝不把连接关闭/超时当作隐含的结束信号（「并且sse要有结束标记」）。前端在第一个 sample 事件到达时就打开结果视图，而不是等整个对比完成；对于一对约 200 页的档案，否则会有好几秒的空白等待（「假设有6对结果（粗加工），可以用sse分6次发，发第一对的时候就开始显示modal，这样是一个很大的提速」）。
