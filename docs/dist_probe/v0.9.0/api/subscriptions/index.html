让某个订阅重新考虑它已经处理过的作品。


「已看过」在其他情况下是永久性的，这对通常情形是正确的——用户故意删掉的作品绝不能在下次检查时回来。但有两种情况需要撤销它：一次误删，以及一条后来被放宽的规则（在旧规则下被拒绝的作品在被拒绝的那一刻就被记为已看过，所以没有任何东西会重新考虑它们）。


带 sources 时只遗忘指定的那些。带 all: true 时清空整个集合——它被保留为一个独立的、显式的请求，因为在长期运行的订阅上，它可能一次匹配到全部历史目录，后果的量级不同。

预览一次检查会做什么，但不真的执行。


它刻意可以作用于已停用的订阅：「这条规则实际会抓到什么」恰恰是在调整一条关掉的规则时问的。不会入队、不会记为已看过、也不会写日志，因此可以安全地反复运行——唯一的代价是向来源发一次请求。
