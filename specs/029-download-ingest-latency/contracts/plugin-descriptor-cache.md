# Contract: 插件声明缓存（`plugin_info` / `plugin_options` 的复用语义）

**Status**: 本特性新增内部契约 | **Type**: crate 内行为契约（`lanrurugi-plugin`），不改变插件 ABI

## 对外可观察的承诺

| 规则 | 内容 |
|---|---|
| P1 | **编辑即生效**：插件 `.ts` 的修改时间或大小变化后，下一次 `plugin_info`/`plugin_options`/`execute` 必须看到新内容，无需重启服务、无需清缓存。 |
| P2 | **上传/删除即生效**：`custom/` 下新增、替换、删除插件后，下一次插件列表请求与下一次入库都必须反映新集合；被删除的插件不得继续出现在结果里。 |
| P3 | **权限不放大**：缓存只保存“声明了什么”。每次真实加载仍以自己的最小授权运行（`--allow-read` 仅 dispatcher/SDK/该插件文件；`--allow-net` 仅该插件声明的域名）。缓存命中**不得**导致任何一次插件调用获得更宽的权限。 |
| P4 | **并发合并**：同一 namespace 的并发发现只产生一次真实加载；等待方读同一结果。 |
| P5 | **失败不缓存**：加载失败（语法错误、导入失败、进程崩溃）时错误原样返回、下一次重试；不得缓存失败，也不得用旧条目冒充成功。 |
| P6 | **保守上限**：即使 `(mtime, size)` 未变，条目超过保守上限（默认 60 s）后也必须重新加载一次，以防“时间戳未变的原地替换”。 |
| P7 | **一致性可见**：插件声明的 `namespace` 与其安装路径推导的 namespace 不一致时，必须至少打一条 warn（每个失效周期一次）并进入诊断捕获，不得静默。 |

## 不改变的部分（明确写清，避免误读）

- 插件 ABI 不变：`pluginInfo()` / `pluginOptions()` / `execMetadata` / `execDownload` 的导出名、入参、返回值语义一律不变；现有 legacy 插件无需改动。
- 常驻执行 worker（`execute` 用的每 namespace 一个进程）的复用与 mtime 重启逻辑不变；插件声明的缓存与执行 worker 的缓存是两件事。
- 插件清单的**枚举**（有哪些 `.ts` 文件）仍是每次现场读目录，不做缓存：目录 `readdir` 本身很便宜，而缓存它会破坏 P1/P2 的即时性。

## 可验证的观测点

- 一次入库期间，因“发现插件”而启动的插件运行时子进程数：从 34 降到 0（插件文件未变时）。
- 编辑任一插件的 `.ts`（只改一行注释）后立刻触发一次插件列表请求：新内容可见的延迟 ≤ 一个请求周期。
- 两个并发入库同时开始时的真实加载次数：每个 namespace 1 次。
