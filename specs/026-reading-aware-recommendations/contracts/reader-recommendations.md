# Contract: 阅读页推荐接口

**Feature**: 026-reading-aware-recommendations | **Route**: `GET /api/reader/recommendations/{id}`

## 请求（不变）

| 参数 | 位置 | 说明 |
| --- | --- | --- |
| `id` | path | 档案 id，或 `TANK_…` 的 Tankoubon id |
| `limit` | query | 1–20，默认 10；越界夹取，不报错 |

## 响应（不变）

```json
{
  "recommendations": [
    { "id": "archive-id", "title": "作品标题", "score": 0.93 }
  ]
}
```

- 数组长度 ≤ `limit`；只有书库里没有任何其它候选时才会是 0（全部读完时有 3 条兜底）。
- `score` 为 `similarity + boost`，夹在 `0.0..=1.0`。
- 不新增字段；不返回阅读进度、档位、是否兜底。前端零改动。

## 语义变化（本特性）

1. 已读完（`ReadBucket::Finished`）的档案**不会出现**在结果里，除非全部候选都已读完——此时退化为相似度前 3。
2. 未读 / 在读 / 进度未知的候选按加成后的分数排序；同分按 `id` 升序。
3. 同一时刻，缓存命中路径（Top-N + 重排缓存）与未命中路径（全量扫描）必须给出相同顺序。
4. LLM 重排失败、未配置或超时，仍返回上述排序结果；不会退化成旧的纯相似度顺序。
5. 重排缓存按「锚点进度 + 候选进度摘要」隔离；进度变化后不会复用旧排序。

## 兼容性

- 旧客户端：不感知排序语义，`id`/`title`/`score` 字段照常可用。
- 旧 Redis：旧重排键不再被读取（键多了 digest 段）；旧 Top-N 只需数量 ≥ 请求的候选数，150 与 100 的旧值都能读。
- `TANK_` 锚点：沿用既有「以最后一个成员为锚点、排除全部成员」规则，加成按该成员的阅读状态计算。
