# Feature Specification: 重复档案检测与智能对比

**Feature Branch**: `feat/share-bind-interface`（沿用当前分支；speckit 无 before 钩子，不新建分支）
**Created**: 2026-11-10
**Status**: Draft
**Input**: 用户要求把 `/duplicates` 从「封面 SHA-1 平铺表格 + 只有删除」改成「本地证据筛候选 + LLM 语义裁决 + grid 卡片 + 智能对比 modal」。

## Context

`/duplicates` 现在是 legacy 的复刻：`find_duplicates` 作业按封面缩略图的 **SHA-1** 分组（`crates/lanrurugi-api/src/duplicates.rs`，写 `LRR_DUPLICATE_GROUPS`），阈值是对十六进制串的汉明距离（默认 5）。两个硬伤：

1. 封面重压缩一次哈希就变，同一本书的两个扫本经常分不到一组；
2. 只有封面像才分组，封面不同但内容同源的（不同译本、裁边版、重扫）抓不到。

页面上是一张平铺表格，每组档案各占几行、只有一个「删除」，既不分组也不给任何判断依据。

同时，`crates/lanrurugi-imgcompare`（逐页感知哈希对齐、拉普拉斯方差比清晰度、汇总建议）在 020 删掉下载队列的文件名冲突路径后**失去了唯一入口**，成了死代码——而它设计的目标恰好就是「两个档案是不是同一作品的不同版本」。

## User Scenarios & Testing

### User Story 1 — 扫描后按组审阅（P1）

用户点「检查重复」，得到若干**卡片**，每张卡是一组疑似重复（≥2 个档案）：并排封面、标题、大小、页数、相似度与一句结论。用户不必自己找「哪两个该比」。

**Acceptance**：10,000 档案的库，扫描作业在有进度、可取消的前提下完成；结果按置信度排序；卡片数量与分组数和作业产出一致。

### User Story 2 — 智能对比（P1）

用户在卡片上点「智能对比」，打开并排对比：两边逐页对齐、页数不等时显示插入/缺失、放大镜、每对页的清晰度判定，以及顶部一句「整体建议保留哪边、为什么」。用户可翻页、跳页，看完关掉不做任何改动。

**Acceptance**：对比只读、不写库；打开第一屏 < 1.5 s（封面与首页已缓存时）；页面对齐结果与 `lanrurugi-imgcompare` 的单测一致。

### User Story 3 — 人工决定（P1）

对比后用户选择：保留 A / 保留 B / 都保留 / 不是重复。前三个只记录决定（删除仍走档案删除，带分类与单行本引用提示）；「不是重复」持久化，之后扫描不再提示这一对，直到其中一个档案内容变化。

**Acceptance**：任何路径都不会自动删除档案；「不是重复」在下次扫描后仍然生效；可以只保留组内的一部分（如 3 个里留 2 个）而不影响其余成员的状态。

### User Story 4 — LLM 语义裁决（P2）

卡片上的结论由 LLM 给出：同一作品的不同扫本 / 不同译本 / 相邻卷 / 无关。输入只有文本与数字（标题、作者与社团标签、语言与翻印标记、页数、大小、清晰度均值），**不发图片**。LLM 不可用时卡片退回纯本地证据（相似度 + 清晰度差），并明确标注「未经过语义复核」。

**Acceptance**：LLM 输出经过校验（枚举合法、置信度范围合法、理由非空），不合法即退回本地结论；同一组的复核结果按「组内容哈希 + 提示词版本」缓存，重复扫描不重复计费。

### User Story 5 — 封面感知哈希（P2）

检测从封面 SHA-1 改为**感知哈希**：重压缩、轻微裁边仍能分到一组。legacy 的 `LRR_DUPLICATE_GROUPS` 继续写（legacy 页面还能看），但判定使用新键。

**Acceptance**：同一封面的 JPEG/WebP 两种编码分到同一组；未变化的档案复用缓存的哈希，不重复解码。

### Edge Cases

- 档案没有缩略图（生成失败）→ 跳过封面哈希，只用元数据证据，卡片标注「无封面」。
- 组内 3 个以上 → 卡片显示全部成员，对比默认取「推荐成员 vs 最像它的一本」，用户可切换对手；组内 5 本以上时卡片折叠为「前 3 + N」，展开后按相似度排序。
- 组内成员可能不是两两都像（A≈B、B≈C，但 A 与 C 差得远）——这是传递闭包造成的「链式组」，卡片必须标出这一点（`B 是中间项`），避免用户误以为整组都是同一本。
- 同一档案被两个组同时命中（连通分量重叠）→ 合并为一组。
- 对比中某档案刚被删除/移动 → 返回明确错误，关闭 modal 并提示重新扫描。
- 页数差距极大（如 20 页 vs 300 页）→ 对齐只对前若干页做，结论标注「页数差异过大，可能不是同一作品」。
- 库很小（< 2 个档案）或没有候选 → 空状态，不报错。

## Requirements

### Functional

- **FR-001** 扫描计算每个档案的封面感知哈希（复用 `lanrurugi-imgcompare::alignment::hash_page`），结果缓存；档案内容哈希不变则复用。
- **FR-002** 候选由封面感知哈希距离 + 元数据证据共同决定：去掉发行标记后的标题相似度、作者/社团标签重合、页数差 ≤ 20%、大小比在 [0.2, 5]。
- **FR-003** 结果按连通分量成组，组内成员数**不设上限**（2、3、4、更多都常见）；UI 以「组」为单位出卡片，卡片必须完整表达「这一组有几本、彼此像到什么程度、建议留哪本」。组内的「最佳成员」由两两判定汇总得出（赢的次数最多者，平票时比页数完整度、再比平均清晰度），不是只看任意一对。
- **FR-004** 逐页比对**只对候选对按需执行**，绝不全库两两解码。
- **FR-005** 新增两个只读接口：
  - 单对：给定两个档案 id，返回对齐结果（`[{a_page, b_page, sharpness_a, sharpness_b, verdict}]`）、页数差、整体建议与理由；
  - 整组：给出一组成员 id，返回两两相似度矩阵与每个成员的页数/大小/平均清晰度，供 N 选一时比较；
  两者都不写库。
- **FR-006** LLM 复核**整组一次**（成员 2–8 个）：输入每个成员的标题、作者/社团、语言与翻印标记、页数、大小、平均清晰度，以及两两相似度；输出整组结论（`same_work` / `different_versions` / `adjacent_volumes` / `unrelated`）、**每个成员各自建议保留还是可删**（可以是「A、C 留，B 删」）、一句 `reason`、`confidence`。成员超过 8 个时按相似度与质量先截断到 8 个再送审，其余在 UI 里仍可见。
- **FR-007** 复核结果按「组成员 id + 内容哈希 + 提示词版本」缓存；不合法输出丢弃并退回本地结论。
- **FR-008** 决定是**逐个成员**的，不是「整组选一个」：每个成员有三种状态 `keep`（保留）/ `discard`（可删）/ `undecided`；另有一层**按对**的 `not_duplicate` 标记。允许「保留 3 个里的 2 个」「保留 A 与 C、删 B」这类组合。决定持久化，且随成员内容哈希失效——内容变了要重新判定。
- **FR-009** `/duplicates` 改为 **grid 卡片布局**，卡片以「组」为单位，布局必须把**分组**与**对比**两个动作放在视觉第一层；每个成员可勾选「保留」，默认全部勾选（即「都留下」是零操作）：
  - 卡片顶部是组头：成员数（`3 个档案`）、最高置信度徽标、结论一句话；
  - 中部是成员横排（封面 + 标题 + 大小 + 页数），**成员数逐个列出**：2–3 个时全部横排并标注两两相似度；4 个以上时首行 3 个 + `+N` 展开，展开后是同一卡片的网格；建议保留的成员带「推荐」角标；
  - 底部是动作区：**「智能对比」为整卡最醒目的主按钮**（整宽、主题强调色）；次级动作是「只保留推荐的」与「保留勾选的 N 个」；溢出菜单放「标记为不是重复（按对）」与「删除未勾选的成员」；
  - 成员上的勾选是**多选**：可以只勾 A 和 C、不勾 B，点「保留勾选的 2 个」后 B 进入 `discard`；
  - 单成员（无候选）的档案不出现卡片——页面只展示有对比价值的组。
- **FR-010** 智能对比 modal 从 `d588c84` 之前的实现恢复并改造：并排翻页、对齐带、放大镜、逐页判定、整体建议；只读。
- **FR-011** 删除只作用于用户显式标为 `discard` 的成员，且仍走现有档案删除流程（先展示分类/单行本引用影响）；从未被标记的成员永不删除。
- **FR-012** 继续写 legacy 的 `LRR_DUPLICATE_GROUPS`，格式不变。
- **FR-013** 扫描是后台作业：有进度、可取消、结果可在作业控制台查看。
- **FR-014** 增量：未变化档案复用缓存哈希；未变化组复用缓存复核结果。
- **FR-015** 不向 LLM 发送任何图像或档案字节。
- **FR-016** 对比页的解码/比对线程不超过可用核数的 30%（遵循仓库的 CPU 上限规则）。
- **FR-017** 新增文案进 en / zh / zh_Hant / ja 四份 locale；新增颜色只进 5 个主题文件，不硬编码。

### Key Entities

- **CoverHash**：档案 id、感知哈希（64 bit）、算法版本、计算时间。
- **CandidatePair**：两个档案、各项证据分数、合成相似度。
- **DuplicateGroup**：成员 id 列表、组内容哈希、最高置信度对。
- **PageComparison**：对齐后的页对、两侧清晰度、逐对判定。
- **ReviewVerdict**：LLM 的 verdict / keep / reason / confidence / 模型标识 / 是否退回。
- **DuplicateDecision**：`keep_a` / `keep_b` / `keep_both` / `not_duplicate`、时间、操作者。

## UI 设计（重点：分组与对比）

页面从上到下三层，信息密度递减：

```
重复档案检测                                    [重新扫描]  [清除结果]
找到 6 组疑似重复 · 共 14 个档案 · 上次扫描 3 分钟前

┌──────────────────────────────────────────────────────────────┐
│ 2 个档案            相似度 96%     同一作品的两个扫本           │
│  ┌─────┐  96%  ┌─────┐                                        │
│  │封面A│ ────► │封面B│   A 273.9 MB · 214 页 · 中文            │
│  └─────┘       └─────┘   B  56.9 MB · 212 页 · 中文            │
│  「B 页面更清晰，但缺 2 页；A 完整」                            │
│  ┌──────────────────────────────────────┐  ┌────┐ ┌────────┐ │
│  │           智能对比（放大镜 + 逐页对齐）│  │保留A│ │ 都保留 │ │
│  └──────────────────────────────────────┘  └────┘ └────────┘ │
└──────────────────────────────────────────────────────────────┘
```

- **组头**回答「这是几本、像到什么程度、结论是什么」；**成员横排**回答「具体是哪几本、差在哪」；**动作区**只有一个主动作。
- 「智能对比」占据卡片底部整宽，是唯一使用强调色的按钮；其余动作是描边按钮或溢出菜单项，避免和主按钮抢视觉。
- 组内有 N 本（N ≥ 3）时：卡片标出最高相似度的那一对与「推荐保留」的成员；「智能对比」默认打开「推荐成员 vs 最像它的一本」，modal 顶部有「换一个对手」下拉，同时提供一个 `N 本一览` 视图（成员 × 页数/大小/平均清晰度/与当前主对比对象的相似度），用于快速判断该留哪本。
- 没有候选的组不渲染；页面空态说明「没有发现疑似重复」并给「重新扫描」。

智能对比 modal 的层级：

```
┌ 智能对比 · 2 个档案 · A ↔ B ────────────────────── [换对手 ▾] [×] ┐
│ A：完整 214 页 · 平均清晰度 182   B：212 页 · 平均清晰度 264       │
│ 建议保留 A、C，B 可删（B 有两页缺失）      [保留勾选] [只留推荐]   │
├───────────────────────────────┬───────────────────────────────────┤
│  A 第 12 页  [放大镜]          │  B 第 12 页  [放大镜]             │
│  ▓▓▓▓ 清晰度 141 ▓▓▓▓          │  ▓▓▓▓ 清晰度 233 ▓▓▓▓  ← 更好     │
├───────────────────────────────┴───────────────────────────────────┤
│ 对齐带： 1–11 ✓   12 ⚠   13–208 ✓   209–210 ✗（B 缺）              │
└───────────────────────────────────────────────────────────────────┘
```

- 顶部固定「建议 + 理由 + 决定按钮」，滚动时仍然可见；建议本身可能是「留 A 和 C、删 B」，头部的按钮按当前勾选执行；
- 中间并排双栏，逐页同步翻页；滚动或按键（←/→）都是两侧一起动；
- 底部对齐带是整段概览：绿=对齐且更清晰方已标出，黄=有差异，红=缺页；点任意格跳到该页；
- 放大镜、对齐带、并排翻页三件套从 `d588c84` 之前的实现恢复（`OverlayPage` / `MagnifierOverlay` / `AlignmentBandOverlay`），只换数据来源。

## Success Criteria

- **SC-001** 同一封面的 JPEG 与 WebP 编码分到同一组（构造夹具验证）。
- **SC-002** 10,000 档案的扫描在 10 分钟内完成，且期间 CPU 不超过 30% 上限。
- **SC-003** 对比接口对 200 页的两个档案返回首屏 < 1.5 s（缓存命中时）。
- **SC-004** 任何自动化路径 0 次删除档案（测试断言：扫描与复核只写缓存与建议键）。
- **SC-005** 「不是重复」标记后，同一对在内容不变时 0 次出现在结果里。
- **SC-006** LLM 输出不合法时 100% 退回本地结论，卡片明确标注。

## Assumptions

- 单用户家庭库，规模 10³–10⁵；不做分布式。
- 缩略图已生成（`thumbhash` 之外的新缓存键由本功能自己维护）。
- LLM 走现有 `FeatureId` 通道与 `llm_prompts.rs`，模型可配置、可关闭。
- 逐页比对基于 `lanrurugi-imgcompare` 的既有管线，不引入新的图像模型。

## Out of Scope（v2）

- 逐页挑选并**合成新档案**（新 id、元数据与引用迁移、旧文件删除）。
- 自动删除或自动合并。
- 跨设备/跨实例的重复检测。
