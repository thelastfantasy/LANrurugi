# Research: 重复档案检测与智能对比

## R1 用什么哈希

**决定**：封面感知哈希，复用 `lanrurugi-imgcompare::alignment::hash_page`（`image_hasher`，
64 bit），不再用封面缩略图的 SHA-1。

**理由**：SHA-1 对重压缩、换编码、加边框全部失效——这正是现在「经常漏」的原因；感知哈希对
这些变化稳定，且 imgcompare 已经在用它做逐页匹配，阈值（汉明 ≤ 6/64）有实测依据。

**被否决**：`thumbhash` 复用（它是字节哈希，语义就是「完全相同」）；dHash（对旋转与裁剪更敏感）。

## R2 怎么找候选而不 O(n²)

**决定**：8 段各 8 bit 的鸽笼分桶。汉明距离 ≤ 7 时，8 段里必有一段完全相同——只比较共享至少
一段的档案。阈值取 7（比逐页的 6 略宽，封面的裁切差异更大）。

**理由**：10 万档案两两比较是 5×10⁹ 次汉明运算，虽便宜但要 5×10⁹ 次 Redis 读；分桶把它压到
「每段桶内比较」。桶内点数过多（某段被大量空白封面占满）时退化为按该段二次分桶，绝不回退成
全量两两。

**被否决**：BK-tree（实现复杂、Redis 里存索引麻烦）；全量两两 + Rayon（大库不可接受）。

## R3 元数据证据

**决定**：候选对必须同时满足：

- 去掉发行标记后的标题相似度 ≥ 0.55（`lanrurugi_scanner::release_markers::clean_title` 后
  做字符三元组 Jaccard），或一方标题为空；
- 页数差 ≤ 20%（缺页数时跳过该条）；
- 大小比在 [0.2, 5]；
- 若双方都有作者/社团标签且完全不重合 → 直接否决（不同作者同一本的概率极低）。

**理由**：只靠封面会把「同系列相邻卷」凑成一组；作者/社团是最便宜的否决信号。

## R4 成组与链式组

**决定**：并查集连通分量成组；组内保留两两相似度矩阵。一个组如果存在一对相似度低于阈值的
成员（A≈B、B≈C、A≉C），标为 `chained`，UI 指出中间项。

**理由**：连通分量会把「链」放大成一整组；不标记的话用户会以为三本都一样而误删。

## R5 决定模型

**决定**：逐成员三态 `keep` / `discard` / `undecided`，默认 `keep`；另加按对的
`not_duplicate`。`discard` 只是标记，删除是显式动作。

**理由**：组里可能有 4 本，其中两本同扫本、一本不同译本、一本缺页——「整组选一个」表达不了。
「都保留」是零操作，避免默认值把用户推向删除。

## R6 LLM 复核

**决定**：每组一次，输入文本与数字（每成员标题、作者/社团、语言/翻印标记、页数、大小、平均
清晰度、两两相似度），输出整组 `verdict` + 每成员 `keep|discard` + `reason` + `confidence`。
输出必须过枚举与范围校验，不合法即丢弃并退回本地结论。缓存键 = 成员 id 排序 + 内容哈希 +
提示词版本 + 模型标识。

**理由**：算法能算「像不像」，算不了「中国翻訳版 vs 日文原版该不该都留」「这是相邻卷不是重复」。
不传图像是因为成本与隐私，且图像结论已经由本地清晰度指标给出。

**被否决**：让 LLM 直接决定删除（不可逆）；每组每对都问（费用与延迟）。

## R7 比对接口

**决定**：`GET /database/duplicates/compare?a=<id>&b=<id>`，`spawn_blocking` 调
`imgcompare::compare_archives`，返回裁剪后的 JSON（成对页、清晰度、裁剪对齐、语言判定、建议、
双方结构与大小）。先同步；若 200 页档案实测 > 1.5 s，再补 SSE 流式（`compare_archives_streaming`
已经支持，前端 modal 恢复的 `useCompareStream` 也还在历史里）。

**理由**：先把功能接通、可测；流式是纯优化，不影响契约语义。

## R8 legacy 兼容

**决定**：扫描仍然写 `LRR_DUPLICATE_GROUPS`（同样的 `dupgp_*` 字段、同样按旧阈值分组），
新判定使用自己的键；`GET /database/duplicates` 旧形状保留。

**理由**：legacy 页面/备份导入还认这个键；破坏它没有收益。

## R9 UI 与组件恢复

**决定**：卡片三区（组头 / 成员行 / 动作区），「智能对比」占整宽；对比 modal 从删除前的提交
恢复 `OverlayPage`、`MagnifierOverlay`、`AlignmentBandOverlay`、`PageItem` 等组件，数据源换成
新接口；「保留」是成员级多选。

**理由**：用户明确要「突出分组与对比」并继续用原来的智能对比界面；重画这三个组件成本高、
视觉也会退步。

## R10 CPU 与作业化

**决定**：扫描是 `jobs` 作业，分阶段上报进度（哈希 x/y、比较 x/y、复核 x/y），可取消；
图像解码与比对用专用 `rayon::ThreadPool`，线程数 `(cores * 3 / 10).clamp(1, 4)`（与
`precompute_worker_budget` 同款），后台作业再叠加 `LoadThrottle` 式退避。

**理由**：仓库既有规则要求新并行工作自限 30%；10 万档案的首次哈希是唯一的重活，必须能停。
