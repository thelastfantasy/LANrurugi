设置页的「资源监视」入口会打开 `/resources` 这个独立页面，上面显示这一台机器上的进程、内存、CPU、PSI、插件进程和 Redis 计数。
它和系统任务管理器（gnome-system-monitor、`htop`）的分工是：那些工具看整机，这里看**LANrurugi 自己**
——哪个插件进程在占内存、队列在等什么、Redis 有多少键、上一次模型调用花了多少。

## 打开才采样，关掉就零占用

面板不是常驻的监控进程。只有这个区块展开时才会建立一条 SSE 连接
（`GET /api/resources/stream`），服务端在第一个观察者到来时才起采样任务；关掉区块或切走标签页，
连接断开，采样任务停止、历史也一起释放。所以它不会在你不用的时候占一个核、也不会往磁盘写任何时序数据。

区块里有 1 秒 / 2 秒 / 5 秒三档刷新。采样器本身固定 1 秒一次，选更长的间隔只是"每 N 帧取一帧"，
不会让采样变慢变省。

## 每个数字都带窗口

CPU 利用率、网络速率这类值需要两次观测才能算出来。刚启动后的第一帧里它们是 `null`（面板显示 `—`），
不是 0——0 和"还不知道"必须能区分开。同理，某一节读不到（非 Linux 上读不到 cgroup、没装 `nvidia-smi`）
时，那一节是 `null` 并且旁边会写明原因。

有一处需要特别留意：cgroup 的 `memory.current` **包含页缓存**。页缓存是可以在有内存压力时被回收的，
所以它涨到几个 GB 并不代表进程真的需要那么多内存。真正代表进程占用的是 `anon`（匿名内存）和
服务进程自己的 RSS，面板把这三行并排列出来就是为了这个对比。

## 面板里有什么

| 分组 | 内容 |
|---|---|
| 服务进程 | RSS、峰值、swap、CPU、线程、文件描述符、累计读写字节 |
| 控制组 | `memory.current`（含页缓存）、anon、file、slab、峰值、`pids.current`、内存 PSI、`memory.events` |
| 运行时 | CPU 核心数、跟踪中的后台任务数、排队任务数 |
| 插件进程 | 常驻 worker（每插件一个进程）逐个列出；临时声明进程的可用 / 进行中 / 累计启动数 |
| 进程树 | 从服务进程出发的真实父子关系，最多 64 条、深度 3 层，超出会标 `truncated` |
| 本地模型 | 当日各功能的调用次数、失败数、tokens；进程内模型的加载状态 |
| 队列 | 下载的进行中 / 排队 / 失败数，后台任务，各阶段 p50 与排队等待 p50 |
| Redis | `used_memory` / RSS / 峰值、碎片率、连接数、每秒操作、各库键数、命中率、上次落盘状态、淘汰键数 |
| 网络 / 缓存 | 累计收发字节与速率；插件声明缓存、元数据预览缓存的命中率 |
| 库 / 存储 | 档案数与总字节；库与临时目录所在磁盘的已用空间、占用率和 inode |
| GPU | 默认关闭（`LANRURUGI_RESOURCE_GPU=1` 打开）：利用率、显存、温度；拿不到就标 `unavailable` |
| 观察者 | 当前连接数、已采样帧数、采样器是否在跑、版本与构建类型 |

## 构建类型会标出来

debug 构建跑同样的功能会慢一截、内存也高一截，所以面板里服务进程的名字会写成
`lanrurugi-server (debug)`。这个标记是编译期决定的，启动参数改不了它。`deno` 进程不带标记——它是
独立程序，不是本项目的构建产物。

## 反馈包里也会带上

「诊断与反馈」→「反馈包」有一项「资源占用」，默认勾选。生成的 ZIP 里多一个 `resources.json`，
内容和面板读到的同形状，但做了脱敏：库和临时目录的绝对路径会变成 `<path>`，带 `?key=` / `&token=`
的 URL 会去掉查询串。采集失败时这个文件仍会写出来，只是里面说明失败原因，而不会让整个反馈包失败。

:::tip[什么时候有用]
"用着用着就卡住了"这类报告，过去只能靠追问。现在反馈包里的 `resources.json` 直接给出当时的
PSI、`memory.events`（有没有 OOM kill）和进程 RSS，能立刻区分"内存真不够"和"某个插件在空转"。
:::

## 通过接口读

`GET /api/resources` 返回一份完整快照，不注册观察者，适合脚本抓一次。
`GET /api/resources/stream?interval_ms=1000` 是面板用的那条 SSE。

两条都需要**真实登录会话**：API token（哪怕是管理员角色）和访客都会被拒绝，因为这些数据里有进程表和
Redis 内部计数。
